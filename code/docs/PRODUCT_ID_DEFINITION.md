# 产品ID定义与数据聚合粒度说明

## 核心概念纠正

### 产品ID = 应用ID（App ID）

**定义**：
- **产品ID** 唯一标识一个应用/产品
- **应用ID** 是数据中的关键列，代表正在投放的应用名称或ID
- **产品ID ≠ 广告主ID**（广告主可管理多个产品）

### 为什么一个产品（应用ID）会有多条数据？

同一个产品（应用ID）在一天内会有多条数据，因为**投放维度不同**：

| 维度 | 说明 | 举例 |
|------|------|------|
| **推广流量** | 推广渠道/位置 | 开屏广告、底部导航、中部信息流 |
| **流量场景** | 流量来源/场景 | 信息流、搜索、推荐 |
| **创意规格** | 创意物料形式 | 大图、视频、素材合集 |
| **转化类型** | 转化目标类型 | 激活、注册、购买、订阅 |

**实际例子**：
```
同一个产品 app_001 在 2026-04-21 可能有这些数据行：
1. app_001 + 开屏 + 信息流 + 视频 + 激活   → 消耗100元，D1 15元
2. app_001 + 底部 + 搜索 + 图片 + 注册   → 消耗200元，D1 20元  
3. app_001 + 中部 + 推荐 + 大图 + 购买   → 消耗150元，D1 18元
...
```

这样，同一个产品的多条数据在不同的投放形式中产生，数据聚合时需要考虑这些维度。

## 系统各模块中的产品ID处理

### 1. 数据加载层（data_loader.py）

**聚合粒度**：
```python
group_keys = ['日期', '应用ID', '推广流量', '流量场景', '创意规格', '转化类型']
# 相同的这6个字段就合并为一条
```

**聚合后的结果**：
- 日期粒度：时间范围 + 应用数量 + 投放维度组合数
- 产品粒度：按应用ID聚合，合并所有投放维度的数据
- 应用粒度：与产品粒度相同（应用ID = 产品ID）

**重要**：即使同一产品有多种投放方式，LTV曲线也是按产品（应用）级别计算，不区分投放维度。

### 4. ML预测层（ml_predictor.py）

**训练粒度**：应用ID + 投放维度
```python
# 训练数据粒度：(日期, 应用ID, 推广流量, 流量场景, 创意规格, 转化类型)
# 但预测时返回的是按应用ID级别的平均D1：
```

- 有助于提升整体预测精度

### 5. 优化与报告层

**优化粒度**：应用ID
- portfolio_optimizer：按应用ID分配预算
- report_generator：按应用ID输出诊断和建议

**预算分配**：
```
应用 A：分配预算 50,000 元
应用 B：分配预算 30,000 元
应用 C：分配预算 20,000 元
...
```

运营人员在广告平台后台需要根据应用级别的建议，在不同投放维度间自己分配预算。

## 与其他ID的区别

| ID类型 | 含义 | 作用 | 聚合粒度 |
|--------|------|------|---------|
| **应用ID** | 产品唯一标识 | 系统决策对象 | 产品级 |
| **广告主ID** | 账户管理者 | 财务/权限管理 | 账户级 |
| **推广流量** | 投放渠道 | 投放位置控制 | 维度级 |
| **流量场景** | 流量来源 | 流量质量控制 | 维度级 |
| **创意规格** | 素材形式 | 素材管理 | 维度级 |
| **转化类型** | 转化目标 | 目标管理 | 维度级 |

## 数据流向示例

```
原始数据：app_001在不同投放形式产生多条数据
         ├─ 形式A: 消耗100, D1收入15
         ├─ 形式B: 消耗200, D1收入20
         └─ 形式C: 消耗150, D1收入18

↓ 数据加载与聚合（按应用ID）

聚合后：app_001
       ├─ 总消耗: 450
       ├─ 总D1收入: 53
       ├─ D1回收率: 11.8%
       └─ LTV曲线: 按应用级计算

↓ 产品诊断（应用ID级）

诊断结果：app_001
       ├─ 等级: B
       ├─ 目标D1: 12.9%
       ├─ 缺口: -1.1pp
       └─ 建议: 维持投放

↓ 预算优化（应用ID级）

优化分配：app_001 → ¥50,000

↓ 运营执行

人工分配：app_001 的 ¥50,000 在不同投放维度间分配
       ├─ 形式A: ¥15,000
       ├─ 形式B: ¥25,000
       └─ 形式C: ¥10,000
```

## 使用建议

### 对系统开发者
- 所有模块中的 product_id 都代表应用ID
- 不要与 广告主ID 混淆
- 理解投放维度的重要性

### 对运营人员
- 系统给出的建议是**应用级别**（以应用ID为单位）
- 需要自己在广告平台后台分配预算到具体的投放形式
- 同一应用的多种投放形式可参考历史效果，优先加大D1好的形式

### 对数据分析
- 查看某个应用的数据时，可以按投放维度分层查看
- 理解为什么同一应用会有不同的D1表现
- 投放维度是理解性能差异的关键维度
