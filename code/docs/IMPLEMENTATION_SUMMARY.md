## 📐 系统的数学模型

### 优化问题定义

```
目标函数：
    max Σ(p) budget(p)

约束条件：
    1. Σ(p) budget(p) ≤ 可用预算B
    2. Σ(p) (现有回收(p) + 新增预算(p) × ROI(p) × 倍率(p)) 
       ≥ (现有消耗(p) + 新增预算(p)) × KPI目标
    3. 根据等级的上限约束：
       - A级：budget(p) ≤ current_spend(p) × 0.5
       - B级：budget(p) ≤ current_spend(p) × 0.2
       - C级：budget(p) ≤ current_spend(p) × 0.1
    4. budget(p) ≥ 0

求解方法：线性规划（PuLP + CBC求解器）
```

### 关键假设与验证

#### ✅ 已验证的假设（来自历史数据）

1. **LTV曲线形态** - D1→D3→D7→D30的倍率关系稳定
   - D3/D1 ≈ 1.29
   - D7/D1 ≈ 1.38
   - D30/D1 ≈ 1.44

2. **回收滞后性** - 月初投放ROI贡献>月末投放
   - 月初：有充足的D7-D30回收窗口
   - 月末：只有D1-D3回收窗口

3. **节假日效应** - 周末和假期的变现优于平日
   - 周末scale=1.25
   - 小长假scale=1.4-1.5
   - 电商节scale=1.7-1.8

#### ⚠️ 待验证的假设（需要扩量实验）

1. **ROI递减曲线** - 消耗增加时ROI是否线性递减
   - 需要扩量测试找到流量上限cap

2. **产品流量上限** - 每个产品是否存在天花板
   - 需要历史扩量数据验证

## 💡 创新亮点

### 1. LTV曲线的加权平滑

```python
curve = product_data × weight + standard_curve × (1 - weight)
weight = min(数据天数 / 10, 1.0)

效果：
- 数据多时相信数据
- 数据少时回归标准
- 防止过度拟合
```

### 2. ROI倍率的动态衰减

```
倍率 = f(距月末天数)

- 月初投：完整倍率 1.44（D30）
- 月中投：部分倍率 1.38（D7）
- 月末投：最小倍率 1.0（D1）

物理含义：自动权衡"当月ROI达标"与"规模最大化"
```

### 3. 启发式降级策略

```
求解器无解 → 启发式分配

按等级权重分配：
  A级：50%
  B级：35%
  C级：15%

保证系统鲁棒性
```

### 4. 多维度诊断

```
产品诊断不只是ROI，还包括：
- 效率状态（A/B/C级）
- 达标缺口（相对KPI）
- 改善空间（剩余天数内能否追上）
- 风险预警（能力下滑、流量异常）
```
