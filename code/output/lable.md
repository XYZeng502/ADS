# 智能预算决策系统 — 报告字段词典

生成时间：2026-05-01

系统每次运行生成 **7 类输出文件**，覆盖产品级日报、投放单元级建议、优化摘要、月度汇总和离线算法验证。

---

## 一、产品级日报 `daily_report_*.csv`

### 概述
每行代表一个产品（应用ID）在预测日的完整诊断快照，包含效率分级、D1预测、ROI缺口、预算分配结果和风险告警。最后一行固定为 **【月度汇总】**，展示全局聚合指标。该表是运营决策的核心参考——每一列回答一个决策问题："哪个产品该加量？哪个该减量？还剩多少天可以调整？"

### 字段详细说明

#### 1.1 基础标识

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 日期 | date | 预测所依据的截止日期。系统使用该日期及之前所有历史数据来训练模型和计算诊断，预测范围从该日期的下一天起至月末。例如日期为 `2026-04-21`，则使用 4月21日及之前数据，预测 4月22日至4月30日的D1和ROI。 |
| 产品ID | str | 产品的唯一标识，即数据中的"应用ID"。一个应用ID对应一个产品，同一产品下可能存在多个投放单元（不同推广流量、流量场景、创意规格、转化类型的组合）。 |

#### 1.2 产品分级

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 等级 | str | 产品效率三级分类，基于历史D1与达标D1的对比：<br>**A级（高效）**：历史D1 ≥ 达标D1，当前回收能力已满足KPI要求，可考虑加量；<br>**B级（中等）**：历史D1接近达标D1（差距在10%以内），维持观察或小幅调整；<br>**C级（低效）**：历史D1 < 达标D1且差距超过10%，短期回收不足但长尾可能补回。<br>等级是后续预算分配和风险控制的基础输入。 |
| 等级判定依据 | str | 等级的量化判定理由，格式如 `D1=69.08% 低于达标D1 6.0pp`，明确指出历史D1值、达标D1值及两者的百分点差距。用于解释"为什么这个产品被分到这个等级"。 |

#### 1.3 优化器与求解器状态

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 优化器状态 | str | 预算分配算法层面的状态：<br>`OptimalLP`=线性规划在ROI约束下成功求得最优分配方案；<br>`GreedyRecovery`=当LP求解器报告不可行（当前ROI缺口太大，即使最优分配也无法达标），自动切换到贪心恢复模式——按边际ROI从高到低贪心选择预算段，优先选出最有助于改善ROI的投放单元。 |
| 求解器状态 | str | 底层数学规划求解器（PuLP/CBC）的返回状态：<br>`SUCCESS`=找到了满足所有约束的最优解；<br>`FALLBACK_INFEASIBLE`=ROI硬约束在当前条件下不可达（已发生ROI缺口过大，即使剩余预算全部投到最优单元也无法补回），系统自动回退到贪心恢复模式，在尽可能改善ROI的前提下给出可执行的预算建议。 |

**判断逻辑**：当看到 `FALLBACK_INFEASIBLE` 时，说明当月ROI已达不可逆的缺口状态，此时应关注"能改善到什么程度"而非"能否完全达标"。报告中的"原预测月末ROI"和"优化后ROI_P20"的对比可以量化改善幅度。

#### 1.4 D1 回收率预测（核心指标）

D1（Day-1 Return Rate）= 首日广告收入 / 消耗金额。D1是广告投放最核心的即时效率指标，直接反映花出去的每一块钱在当天收回多少。

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| D1回收率(历史) | float | 该产品在整个历史周期内的加权平均D1。计算方式：`sum(首日广告收入) / sum(消耗金额)`，而非逐日D1的简单平均。这反映了该产品的"长期能力基线"——在不考虑当前趋势的情况下，该产品每投入1元平均能当天回收多少。值越高产品越优质。典型值范围 0.3~1.2。 |
| D1回收率(ML预测) | float / `-` | LightGBM梯度提升树模型对该产品在剩余日期（截止日到月末）的D1均值预测。模型综合了以下信息：<br>- 日期特征（星期几、是否周末、月中进度）<br>- 节假日特征（工作/周末/短假/长假/电商节的one-hot编码+强度因子）<br>- 投放维度特征（推广流量、流量场景、创意规格、转化类型）<br>- 产品基线（历史D1中位数、标准差、活跃天数）<br>- 近期趋势（最近3天/7天的D1和消耗均值、趋势偏离度）<br>显示为 `-` 表示LightGBM未成功训练（数据不足50条或包未安装），此时系统降级使用产品中位数作为兜底预测。 |
| ML vs 历史差值 | float / `-` | 模型预测D1减去历史D1的差值。**正值**=模型认为该产品的D1在剩余期间会高于历史均值（趋势向好，可能是近期数据在改善）；**负值**=模型认为D1会走低（趋势走弱，近期数据在下滑）。该差值直接影响风险告警的触发——当差值为显著负值且近期趋势持续下行时，会触发"产品能力下滑"告警。 |
| D1预测P20(分配单元加权) | float / `-` | 该产品所有被分配了预算的投放单元中，LightGBM预测的D1 P20分位数（20%分位点即保守估计），按各单元的分配预算额加权平均。**P20的含义**：模型认为该单元有80%的概率实际D1不低于此值。用于联合优化的ROI约束——系统要求P20保守预期下的ROI也必须满足KPI，从而在预算分配中内置安全边际。 |
| D1预测P50(分配单元加权) | float / `-` | 同上，D1 P50中位数预测（模型认为实际D1有一半概率高于此值、一半概率低于此值）。代表模型对该产品分配单元的"中性预期"。 |
| D1预测P80(分配单元加权) | float / `-` | 同上，D1 P80分位数预测（乐观估计，模型认为只有20%概率实际D1高于此值）。用于观察该产品潜在的上行空间。 |

**D1分位数体系的设计理念**：广告投放天然存在不确定性，同一单元每天的D1会波动。系统同时输出P20/P50/P80三个分位数，形成"保守-中性-乐观"的三层预期，让决策者可以：
- 用P20做安全预算（确保即使偏保守也能达标）
- 用P50做中性规划（最可能的回收水平）
- 用P80评估上行潜力（如果运气好能多回收多少）

#### 1.5 ROI 相关指标

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 达标D1 | float | 该产品在当前LTV曲线下，达到KPI目标所需的最低D1。计算公式：**达标D1 = KPI / M(月内剩余天数)**，其中M是LTV累计倍率函数 M(t) = a × ln(t) + b。例如：KPI=1.05，月内LTV总倍率=1.40，则达标D1=0.75，含义是"每天投入1元需要在当天收回0.75元，加上后续30天长尾回收，最终才能达到1.05的总ROI"。 |
| 当前ROI | float | 该产品在当月截止预测日的实际ROI。计算方式：`当月累计变现金额 / 当月累计消耗金额`。注意：变现金额使用Cohort矩阵法精确计算——每笔消耗按其已存活天数对应的LTV倍率折算回收（而非直接使用粗粒度的"30日累计变现金额"列，后者对近期投放可能为空）。 |
| KPI | float | 目标ROI，默认1.05即105%——每投入1元需要回收1.05元。这是整个系统的核心约束条件，所有预算分配、产品诊断、风险控制都围绕此目标展开。 |
| ROI缺口(pp) | float | KPI减去当前ROI，单位为百分点（percentage point，简称pp）。正值=缺口/未达标（当前ROI低于目标），负值=盈余（当前ROI高于目标）。例如当前ROI=0.93、KPI=1.05，ROI缺口=12.1pp。此值越大，达到KPI的难度越大。联合优化器会据此决定是释放更多预算（盈余时）还是收紧预算（缺口时）。 |
| 组合预测ROI_P20 | float / `-` | 联合优化后的全产品组合月度ROI预测，使用各分配单元的P20（保守）D1预测加权计算。这是系统最核心的"安全预测"——在保守假设下，按建议的预算分配方案执行后，月末预计达到的ROI。如果此值 ≥ KPI，说明即使在保守预期下方案也是安全的。 |
| 组合预测ROI_P50 | float / `-` | 同上，使用P50中性预测。对比P20和P50可以判断预测的不确定性——两者差距越大，预测越不确定。 |
| P20安全垫(pp) | float / `-` | 组合预测ROI_P20减去KPI，单位百分点。**正值**=在保守预期下预计能超额达标（安全），可以适度追加预算；**负值**=保守预期下达不到KPI（有风险），需要谨慎或收紧。这是月度汇总行的关键指标——直接回答"这个月还能不能达标"的问题。 |

#### 1.6 消耗与回收

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 累计消耗 | float | 该产品当月累计消耗金额（元），截止到预测日。注意：这是聚合后数据中该产品所有投放单元的消耗总和。 |
| 累计回收 | float | 该产品当月累计变现金额（元），使用Cohort矩阵法计算——每一笔历史消耗按其投放日期至今已存活的天数，乘以对应的LTV累计倍率，得到该笔消耗截止预测日已产生的回收。这种方法避免了直接使用"30日累计变现金额"列的缺陷（对投放不满30天的新客，该列可能为空或预估值不准确）。 |
| 活跃天数 | int | 该产品当月有消耗记录的天数。产品可能并非每天都投放，此字段反映投放的连续性。活跃天数越接近当月已过天数，说明该产品投放越连续稳定。 |
| 历史日均消耗 | float | 累计消耗 / 活跃天数（元/天）。反映该产品平均每天花多少钱，是设定预算上限（Cap）和日均建议预算的基础参考值。 |

#### 1.7 预算分配结果

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 建议日均预算 | str | 系统为该产品推荐的每日预算（元/天）。生成逻辑：<br>1. 如果联合优化器对该产品有分配结果（即 `分配总额` 有值），日均预算 = 分配总额 / 分配覆盖日期数；<br>2. 如果联合优化器未分配（ROI不可达回退），则按产品等级给出兜底建议：<br>   - A级产品：历史日均消耗 × 1.5（加量，因为有能力）<br>   - B级产品：历史日均消耗 × 1.0（维持）<br>   - C级产品：历史日均消耗 × 0.5（减量，因为低效）<br>带有 `*` 标记的值表示是系统自动推算的兜底值，非联合优化精确解。 |
| 分配总额 | float / `-` | 联合优化器为该产品在所有剩余日期分配的总预算（元）。`-` 表示该产品未被联合优化器选中（可能是该产品所有单元在P20约束下都达不到KPI，或预算已耗尽）。分配总额 = 该产品各投放单元 × 各日期的分配预算之和。 |
| 分配单元数 | int | 该产品被分配了正预算（>0）的投放单元数量。一个投放单元 = 推广流量×流量场景×创意规格×转化类型的组合。此值反映了预算在该产品内部的分散程度——分配单元数多且每单元预算小=分散投放；分配单元数少且每单元预算大=集中投放。 |
| 分配覆盖日期数 | int | 该产品被分配预算覆盖的剩余日期数（从预测日下一天到月末）。如果该产品只在部分日期被选中（例如仅周末有分配），此值会小于剩余总天数，说明系统认为该产品在某些日期更有价值。 |
| 分配Cap | float | 该产品所有被分配单元的风险预算上限总和。Cap = 各单元历史日均消耗 × 风险折扣 × 节假日Scale。Cap的作用是防止系统对单一单元或产品过度加量——即使该单元预测ROI很高，预算也不能超过其历史消耗的合理倍数。 |
| Cap使用率 | float / `-` | 分配总额 / 分配Cap。=1.0 表示充分利用了可用上限；<1.0 表示未用完（可能是预算约束限制了总额，或该产品可分配的优质单元不足）；通常不会超过1.0（除非存在四舍五入）。 |
| 分配预算占总建议 | float | 该产品分配总额占所有产品分配总额的比例（0~1）。反映了该产品在全局预算中的相对重要性。例如0.35表示该产品拿到了35%的总预算。 |

#### 1.8 单元级聚合指标（从投放单元加权到产品级）

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 分配单元P20边际ROI | float / `-` | 该产品所有分配单元的 segment_roi_p20（边际月内ROI P20）按分配额加权均值。segment_roi_p20 = D1_P20 × LTV倍率。此值是该产品"在保守预期下每投入1元能产生的月内总回收"，直接影响该产品在联合优化中的排序优先级——边际ROI越高的单元越优先获得预算。 |
| 分配单元P50边际ROI | float / `-` | 同上，基于D1_P50的边际ROI。对比P20和P50边际ROI可以判断该产品预测的不确定性。 |
| LTV倍率(分配加权) | float / `-` | 该产品分配单元的平均LTV总倍率（按分配预算加权）。LTV倍率 = M(该日期到月末的天数) = a × ln(days) + b，反映"该日期的投放到月底还能产生多少倍于D1的累计回收"。越接近月初的值越大（因为剩余时间长），越接近月末的值越小（趋近于1.0即只有首日回收）。 |

#### 1.9 风险控制

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 风险预算折扣 | float | 风险控制乘数，范围 0~1。由产品诊断模块根据以下信号自动判定：<br>- 最近3天D1相比历史均值的下滑幅度<br>- 最近7天D1的趋势方向<br>- 产品是否处于"能力下滑"状态<br>判定逻辑：下滑 < 10% → 折扣=1.0（无降权）；下滑 10-30% → 折扣=0.85（轻度降权）；下滑 30-50% → 折扣=0.425（明显降权）；下滑 > 50% → 折扣=0.1（接近暂停）。折扣直接作用于Cap，降低风险产品的预算上限。 |
| 风险预算动作 | str | 与风险折扣对应的预算决策建议：<br>`正常`=折扣=1.0，预算不受限；<br>`轻度降权`=折扣=0.85，小幅降低预算上限；<br>`明显降权`=折扣≈0.4，显著降低预算上限；<br>`暂停`=折扣≈0.1，基本暂停投放。 |

#### 1.10 改善评估与风险告警

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 调优方向 | str | 基于产品等级、改善窗口和当前趋势的综合建议：<br>`加量`=产品高效（A级）或趋势明确向好，建议增加预算以获取更多低风险回收；<br>`减量或维持观察`=产品暂时低效（C级）但长尾可能补回，不建议立刻暂停；<br>`按KPI下限运行`=产品ROI已经接近临界，需要严格按最低可接受ROI来控制投放。 |
| 改善可行性 | str | 在剩余天数内，该产品是否能通过调整预算使ROI改善至达标水平。判定逻辑基于LTV曲线：计算在最大可能倍率下还需要多少D1提升，对比D1自然波动范围判断能否达到。`是`=存在改善空间；`否`=在当月时间窗口内基本无望达标。 |
| 剩余改善天 | int | 从预测日下一天到月末的天数。随着时间推移此值递减，越接近月末改善空间越小。 |
| 临近截止 | str | 是否临近改善窗口关闭。当剩余改善天 ≤ 3时标记为 `⚠️ 是`，此时即使立刻调整预算，由于LTV累积时间太短，对当月ROI的影响也非常有限。这是运营的"最后调整机会"信号。 |
| 风险告警 | str | 该产品触发的风险信号汇总，多个告警以 `; ` 分隔。告警类型包括：<br>`[产品能力下滑]`=最近3天D1显著低于历史均值，产品回收能力在恶化；<br>`[ROI持续恶化]`=连续多日ROI走低；<br>`[消耗异常]`=消耗金额出现异常波动（暴涨或暴跌）。<br>每条告警包含严重程度（high/orange）、具体描述和量化数据。空字符串=无告警。 |
| 诊断说明 | str | 产品诊断的文字总结，综合了等级、趋势、改善空间三个维度的判断。例如："该产品短期低效，但长尾可能补回，建议观察或小幅减量"。这是面向运营人员的最终文字建议。 |

## 二、投放单元级建议 `daily_report_units_*.csv`

### 概述
这是系统最细粒度的输出——每行代表一个投放单元 × 一个建议日期。投放单元是产品的子维度，由四个投放参数组合定义：推广流量（渠道）、流量场景（场景类型）、创意规格（素材类型）、转化类型（目标行为）。该表回答"在具体某一天、对某个产品的某个具体投放方式，应该投多少钱，预计能回收多少"。

该表有两种输出模式，由 `输出类型` 字段区分：
- **候选排序模式**：当预算为0（优化器无可行解）时，系统仍会输出所有单元按边际ROI的排序，供人工参考
- **实际分配模式**：当优化器有解时，仅输出被分配了正预算的单元，含具体预算金额

### 字段详细说明

#### 2.1 基础标识

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 报告日期 | date | 预测所依据的截止日期。与日报中的 `日期` 含义一致，使用该日期及之前的历史数据。 |
| 输出类型 | str | `候选排序`=无预算可分配（ROI约束不可达或预算为0），表中数据仅用于展示排序，`建议预算` 列全为0；`实际分配`=联合优化有可行解，表中数据为实际建议的预算分配方案。 |
| 建议日期 | date | 建议在该日期进行投放。范围从预测日下一天到月末最后一天。不同日期的LTV倍率不同——越早投放，到月末累积的长尾回收越多，因此同等D1下月初的"边际ROI"高于月末。 |
| 产品ID | str | 投放单元所属的产品（应用ID）。 |
| 推广流量 | int | 投放维度之一：推广流量的编码值。代表投放渠道（如不同广告平台或流量来源）。编码值对应实际渠道名称（映射关系在数据CSV中）。 |
| 流量场景 | int | 投放维度之一：流量场景的编码值。代表广告展示的场景类型（如信息流、开屏、激励视频等）。 |
| 创意规格 | int | 投放维度之一：创意规格的编码值。代表广告素材的规格类型（如图片尺寸、视频时长等）。 |
| 转化类型 | int | 投放维度之一：转化类型的编码值。代表优化目标行为（如安装、注册、付费等）。 |

#### 2.2 预算与D1预测

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 建议预算 | float | 联合优化器为该单元×日期组合建议的预算金额（元）。0=该组合未被选中（候选排序模式下所有值均为0）。正值的分配逻辑：优化器在ROI约束下，按各单元的边际ROI从高到低选择，高ROI单元优先获得预算（直到其Cap耗尽），直到总预算分配完毕或所有单元都已分配至Cap。 |
| 建议日预算 | float | 同 `建议预算`，以日粒度展示。通常与建议预算相同（因为每行已经是一个日期）。 |
| D1预测P20 | float | LightGBM分位数回归模型对该单元在建议日期的D1 P20预测（保守估计，80%概率实际值在此之上）。模型同时利用该产品的历史趋势和该投放单元的特征（4个维度的编码值作为categorical特征）进行预测。分位数通过训练三个独立的LightGBM模型（α=0.2/0.5/0.8）得到，确保分位数校准。 |
| D1预测P50 | float | 同上，D1 P50中位数预测——模型认为该单元在该日期最可能的D1水平。 |
| D1预测P80 | float | 同上，D1 P80乐观预测——该单元潜在的上行空间。 |

**P20/P50/P80的使用建议**：P20用于做ROI达标的保守预算规划（"即使偏悲观也能达标"）；P50用于内部收益率测算；P80用于识别高潜力投放机会。P20与P80差距大说明该单元不确定性高，建议用小额预算测试。

#### 2.3 ROI 预测与排序

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 月内LTV倍率 | float | 该建议日期到月末的天数对应的LTV累计回收倍率。计算公式：M(d) = a × ln(d) + b，其中d=建议日期到月末的天数，a和b是该产品的LTV曲线拟合参数。例如某单元的LTV倍率=1.16，表示该日在D1回收的基础上，到月底还会额外累积16%的长尾回收（第2-30天的累计）。月初的值通常较高（1.3-1.5），月末趋近于1.0。 |
| 单元ROI_P20 | float | 该单元×日期的P20预期月内ROI。计算公式：**D1_P20 × LTV倍率**。这是联合优化器中的核心排序指标——优化器要求每个被选单元的ROI_P20 ≥ KPI（即P20保守预期下也必须达标），从而在预算分配中内置安全边际，过滤掉"只有乐观预期才达标"的投机性投放。 |
| 单元ROI_P50 | float | 同上，P50中性预期ROI。对比ROI_P20和ROI_P50可以了解预测的波动范围。 |
| expected_roi_p80 | float | P80乐观预期ROI。如果P80_ROI很高但P20_ROI不达标，说明该单元"高赔率但低胜率"——适合小预算试探而非大规模投放。 |
| p20_margin_pp | float | 单元ROI_P20 − KPI（百分点）。**正值**=即使保守预测也达标（安全优质单元，应优先分配预算）；**负值**=保守预测下达不到KPI（风险单元，优化器会跳过或仅分配极少量预算）。这是联合优化中最关键的筛选条件。 |
| p50_margin_pp | float | 单元ROI_P50 − KPI。P20不达标但P50达标的单元属于"中间地带"——有一定风险但中性预期可行，适合酌情分配。 |
| candidate_rank | int | 该单元在所有候选单元中的全局排序（1=最优）。排序依据：P20边际ROI降序。rank越小的单元被优先选中分配预算。运营人员可以关注top-ranked单元的特征（哪些渠道/场景/创意/转化类型组合表现最好），为素材和投放策略优化提供方向。 |

#### 2.4 预算约束与风险控制

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 原始Cap | float | 该单元×日期的原始预算上限。计算公式：该单元的历史日均消耗 × 节假日Scale。历史日均消耗 = 该单元当月累计消耗 / 该单元当月活跃天数。Cap确保系统不会对单个单元过度加量——即使预测ROI很高，预算也不应远超历史消耗水平，因为模型预测在远离训练数据时会失效。 |
| 风险后Cap | float | 考虑产品级风险折扣后的实际预算上限。计算：原始Cap × 风险折扣。当产品出现能力下滑时，风险折扣 < 1，Cap被压缩，从而限制在该产品各单元的总投入。这是系统风险控制机制的关键环节。 |
| 风险折扣 | float | 该单元所属产品的风险折扣乘数（与日报中的 `风险预算折扣` 相同）。同一产品下所有单元共享相同的风险折扣。 |
| 节假日Scale | float | 该建议日期的节假日投放系数（≥1.0）。例如劳动节期间Scale=1.25，周末Scale=1.05，普通工作日Scale=1.0。高Scale日期往往是流量高峰，用户活跃度和转化率更高，因此Cap也相应上调以允许更多预算。 |
| 历史消耗权重 | float | 该单元在其产品内的历史消耗占比（0~1）。计算：`该单元当月累计消耗 / 该产品当月累计消耗`。用于在聚合D1预测和ROI指标时按消耗加权，使得大消耗单元对产品级指标的影响更大。 |
| KPI | float | 目标ROI（默认1.05），作为每行的固定参照值。 |

## 三、优化效果摘要 `optimization_summary_*.csv`

### 概述
全局视角的优化前后对比表（通常只有1行）。这是向管理层汇报的"一页纸"摘要——用最精简的指标回答：优化能带来多大改善？需要多少预算？预计回收多少？

### 字段详细说明

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 日期 | date | 预测日期 |
| 优化器状态 | str | 同日报，此处为全局最终状态。 |
| 求解器状态 | str | 同日报。 |
| KPI | float | 目标ROI（默认1.05）。 |
| 当前ROI | float | 当月截止预测日的实际ROI = 已发生回收 / 已发生消耗。注意此处的"回收"是Cohort矩阵计算的精确值，而非简单的30日累计变现加总。 |
| 原预测月末ROI | float | **不进行任何预算调整**情况下，按当前消耗节奏继续投放预计达到的月末ROI。计算方式：`(已发生回收 + 历史长尾回收 + 未来新客按当前D1均值预测的回收) / (已发生消耗 + 未来按当前日均消耗预测的消耗)`。这是优化的"基线"——衡量不做任何改变会得到什么结果。 |
| 优化后ROI_P20 | float | 按联合优化器建议的预算分配方案执行后，在保守假设下（所有单元取P20 D1）的预计月末ROI。计算方式：`(已发生回收 + 历史长尾回收 + 未来P20回收) / (已发生消耗 + 建议释放预算)`。**这是系统最关键的单值输出**——直接回答"按建议执行后，保守预期下能达标吗？"。 |
| 优化后ROI_P50 | float | 同上，使用中性假设（P50 D1）。对比P20和P50可以量化预测不确定性。 |
| P20安全垫(pp) | float | 优化后ROI_P20 − KPI。这是系统回答"安全吗"的核心指标：正值=保守预期也能达标，负值=即使优化后保守预期仍有缺口。 |
| 建议释放预算 | float | 联合优化器建议在剩余日期投入的预算总额（元）。这是"该花多少钱"的答案——不是拍脑袋的数字，而是在ROI约束下求解出的最大可行预算。 |
| 预算利用率 | float | 建议释放预算 / 所有候选单元的风险后Cap总和。反映了预算约束的松紧程度——接近1.0说明优质单元供应充足，预算受限；远低于1.0说明优质单元不足，有多余Cap但无法利用（因为其ROI不达标）。 |
| 历史长尾回收 | float | **已投放用户在剩余日期将自然产生的回收**（元）。计算逻辑：对每一笔历史消耗，用LTV曲线推算其从当前日期到月末的额外回收 = D1 × [M(到月末) − M(已存活)]。这部分回收不需要额外预算——已经在账上，只是随时间逐步释放。这是ROI预测中常被忽略但非常重要的组成部分。 |
| 未来回收_P20 | float | 新分配预算按P20 D1预测在月内产生的回收（元）。计算：Σ(分配预算 × D1_P20 × LTV倍率)。注意不包含历史长尾回收。 |
| 未来回收_P50 | float | 同上，使用P50 D1预测。 |
| 已发生消耗 | float | 当月已实际消耗的总金额（元）。截止预测日的累计值。 |
| 已发生回收 | float | 当月已实际产生的总回收（元），使用Cohort矩阵法计算：每笔消耗按其已存活天数×LTV倍率折算。**这个值可能不同于数据库中直接存储的"30日累计变现金额"**，后者对新投放的Cohort可能不准确。 |

**封面摘要阅读顺序建议**：
1. 先看 `当前ROI` 和 `P20安全垫(pp)`，判断整体健康度
2. 再看 `原预测月末ROI` vs `优化后ROI_P20`，判断优化能带来的改善幅度
3. 最后看 `建议释放预算` 和 `预算利用率`，判断执行方案需要的资源

## 四、算法验证报告 `validation_report_*.md`

### 概述
Markdown格式，通过**时间切分**（而非随机切分）模拟真实预测场景：用较早时段的数据训练模型，用最晚几天的数据验证预测准确度。这避免了数据泄漏——训练集和验证集在时间上不重叠，模拟了"用过去预测未来"的真实使用方式。

### 章节说明

#### 4.1 数据切分详情

| 字段 | 说明 |
| --- | --- |
| train_start / train_end | 训练集的时间范围。例如 2026-03-01 至 2026-04-14，覆盖约45天数据。 |
| validation_start / validation_end | 验证集的时间范围。默认取数据最后7天（如 2026-04-15 至 2026-04-21）。这7天的数据不在训练集中出现，完全模拟"预测未来"场景。 |
| train_rows / validation_rows | 训练/验证集的投放单元×日期样本总数。验证集约占总样本的10-15%。 |
| train_days / validation_days | 训练/验证覆盖的天数。 |
| train_products / validation_products | 训练/验证覆盖的产品数（应用ID去重）。通常两者相同（所有产品在全部时段都存在）。 |
| LightGBM分位数模型训练状态 | `已训练`=三个分位数模型（α=0.2/0.5/0.8）均训练成功；`未训练`=训练数据不足，验证结果使用产品均值基线。 |

#### 4.2 D1 预测验证指标（详细解释）

| 指标 | 详细说明 |
| --- | --- |
| 样本数 | 验证集中消耗>0且实际D1在有效范围（0~2.0）内的样本数。排除了无消耗或异常值的单元。 |
| 验证消耗 | 验证集所有样本的消耗金额总和（元）。用于加权计算——大消耗样本对加权指标的影响更大。 |
| 模型MAE | 模型P50预测值与实际D1的平均绝对误差（等权）。MAE越小越好。例如MAE=0.23表示模型预测的D1平均偏离实际值23个百分点。 |
| 基线MAE | 产品历史均值D1与实际D1的平均绝对误差（等权）。用产品的长期均值去预测每个具体单元的D1，作为最简单的对照基线。 |
| MAE提升 | 模型相对基线的MAE改善幅度 = (基线MAE − 模型MAE) / 基线MAE。正值=模型优于简单基线，负值=模型更差。 |
| 模型加权MAE | 按消耗金额加权的模型MAE。权重=该样本消耗 / 总消耗。加权后更能反映"大钱投到哪里去了"的预测质量——花大钱的单元预测准不准比花小钱的更重要。 |
| 基线加权MAE | 按消耗金额加权的基线MAE。与模型加权MAE对比，判断模型是否在重要投放上比简单基线做得更好。 |
| 加权MAE提升 | (基线加权MAE − 模型加权MAE) / 基线加权MAE。这是最关键的验证指标——**模型在大消耗投放上是否显著优于简单均值？** 如果此值为正且较大（如60%），说明模型在实际花钱的地方预测更有价值。 |
| P20覆盖率 | 实际D1 ≥ 模型P20的样本数 / 总样本数。**理想值约80%**。如果明显高于80%（如95%），说明P20过于保守（低估了实际D1），可以适当放松约束；如果明显低于80%（如60%），说明P20过于乐观（高估了实际D1），约束被频繁突破，需要收紧。 |
| P80覆盖率 | 实际D1 ≤ 模型P80的样本数 / 总样本数。**理想值约80%**。同上，偏离80%说明分位数校准有问题。 |
| P20_P80区间覆盖率 | 实际D1落在P20和P80之间的样本占比。**理想值约60%**（80%的上半部分与80%的下半部分的交集）。反映模型对不确定性的刻画能力——区间覆盖率越高，说明模型给出的预测区间越可靠。 |
| P20平均保守余量 | P20 − 实际D1 的均值。正值=P20平均来说比实际D1低这么多（保守了），负值=P20平均来说高于实际D1（乐观了/危险）。用于校准分位数模型的保守程度。 |

#### 4.3 同等预算离线排序验证

这是模拟"如果按模型排序来分配预算，实际效果会怎样"的离线测试。核心思想：**同等预算下，按模型排序选的单元 vs 按旧方法（产品均值）选的单元，谁的实际D1更高？**

| 指标 | 详细说明 |
| --- | --- |
| 分配预算 | 两种策略使用完全相同的预算总额。从所有候选单元的Cap中按一定比例提取（模拟实际可操作预算）。保证比较的公平性——不是比谁花钱多，而是比同等钱花在谁身上效果更好。 |
| 选择单元数 | 在给定预算下，每种策略选出的投放单元数量。通常新算法选出的单元数更少（更集中）→说明模型筛选更严格，只选最优的。 |
| 实际D1 | 选出单元在验证日的**真实加权平均D1**（按分配预算加权）。这是无法造假的金标准——"你说这些单元好，它们在验证日实际表现如何？"。新算法此值应高于基线。 |
| 实际月内ROI代理 | 实际D1 × LTV倍率。因为验证日之后还有长尾回收，用LTV倍率将D1外推到月内ROI的近似值。用于近似比较两种策略对月度ROI的实际影响。 |
| 平均排序分 | 选出单元的加权平均排序分数。新算法用P20边际ROI排序，基线用产品历史D1排序。用于分析排序机制本身的合理性。 |
| 平均LTV倍率 | 选出单元的加权平均LTV倍率。如果新算法在月初偏重的单元多，此值会更高；如果在月末偏重，此值低。用于分析策略的时间偏好。 |

**两种策略的对照含义**：
- **产品均值基线**：代表"传统做法"——按产品的历史D1水平从高到低挑单元，好产品的所有单元都给预算
- **新算法P20排序**：代表"智能做法"——按模型对每个具体单元的P20边际ROI排序，能区分同一产品内不同投放单元的质量差异

如果新算法在同等预算下实际D1和实际月内ROI代理均显著高于基线，说明模型确实学到了产品均值无法捕捉的单元级差异信号。

## 五、D1 预测验证明细 `validation_prediction_detail_*.csv`

### 概述
验证集所有有效样本的逐条预测对比。每行=一个投放单元×验证日期。用于深入诊断模型在哪些类型的单元上预测好/差，以及分位数是否校准。

### 字段详细说明

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 日期 | date | 验证日期（属于验证时间段内，模型训练时未见过的日期）。 |
| 产品ID | str | 产品标识。 |
| 推广流量 | int | 投放维度编码。 |
| 流量场景 | int | 投放维度编码。 |
| 创意规格 | int | 投放维度编码。 |
| 转化类型 | int | 投放维度编码。 |
| 消耗 | float | 该单元在该日期的实际消耗金额（元）。消耗越大，该样本在加权评估中的权重越高。可用此列筛选"大消耗样本"单独分析模型在重要投放上的表现。 |
| 实际D1 | float | 该单元在该日期的真实D1回收率 = 首日广告收入 / 消耗金额。这是预测的"真实标签"。 |
| 模型P20 | float | LightGBM分位数模型（α=0.2）对该样本的D1预测值。训练时使用quantile regression loss。 |
| 模型P50 | float | LightGBM分位数模型（α=0.5）预测值——模型的"点估计"。 |
| 模型P80 | float | LightGBM分位数模型（α=0.8）预测值。 |
| 产品均值基线 | float | 该产品的历史加权平均D1，作为最简单的对照预测。模型的目标是超越这个基线。 |
| 模型绝对误差 | float | `abs(模型P50 − 实际D1)`。衡量模型预测偏离实际的程度。可按产品、投放维度分组统计此值，识别模型的薄弱环节。 |
| 基线绝对误差 | float | `abs(产品均值基线 − 实际D1)`。与模型绝对误差逐一对比——哪行模型误差更小，哪行模型就赢了基线。 |
| P20命中 | int (0/1) | 1=实际D1 ≥ 模型P20（保守约束未被突破），0=实际D1 < 模型P20（保守约束被突破，实际比保守预期还差）。此列汇总得到P20覆盖率。 |
| P80命中 | int (0/1) | 1=实际D1 ≤ 模型P80（实际未超出乐观上界），0=实际D1 > 模型P80（实际比乐观预期还好——好消息但有信息损失）。 |
| P20_P80区间命中 | int (0/1) | 1=实际D1落在 [P20, P80] 区间内。同时满足P20命中且P80命中。此列汇总得到区间覆盖率。 |
| P20保守余量 | float | 模型P20 − 实际D1。**正值**=模型低估了实际D1（保守了），**负值**=模型高估了实际D1（危险，保守约束被突破）。可以绘制此值的分布直方图来评估保守程度是否合理——理想情况是正值和负值平衡在0附近，且负值比例约20%。 |
| P50误差 | float | 模型P50 − 实际D1（保留符号的误差）。**正值**=模型高估，**负值**=模型低估。可以绘制误差分布图来检查模型是否存在系统性偏差（例如总是高估低D1的单元）。 |

## 六、预算排序验证明细 `validation_allocation_detail_*.csv`

### 概述
离线排序测试的逐单元明细。每行=被某策略选中的一个投放单元×日期（两种策略的行在结构上并列，通过"策略"列区分）。用于深入分析：新算法选了哪些单元而基线没选？新算法跳过了哪些基线会选的单元？不同策略的选择在实际表现上有何差异？

### 字段详细说明

| 字段 | 类型 | 详细说明 |
| --- | --- | --- |
| 日期 | date | 验证日期。 |
| 策略 | str | 区分两种排序策略：`新算法P20排序`=按模型P20边际ROI降序选择，`产品均值基线`=按产品历史D1降序选择。两种策略使用同等总预算。 |
| 产品ID | str | 产品标识。 |
| 推广流量 | int | 投放维度编码。 |
| 流量场景 | int | 投放维度编码。 |
| 创意规格 | int | 投放维度编码。 |
| 转化类型 | int | 投放维度编码。 |
| 分配预算 | float | 分配给该单元的预算金额（元）。两种策略的分配总额相同，但分配到具体单元上的金额不同。 |
| 排序分 | float | 该策略用于排序的依据值：<br>- 新算法策略：segment_roi_p20（P20边际月内ROI），值越高越优先<br>- 产品均值基线策略：产品历史D1，值越高越优先<br>排序分不直接等于实际ROI，而是"模型/经验认为它会有多好"。 |
| 实际D1 | float | 该单元在验证日的真实D1。**这是验证排序质量的终极标准**——如果排序分高的单元实际D1也确实高，排序就是有效的。 |
| 月内LTV倍率 | float | 从该验证日期到月末的LTV累计倍率。用于计算"实际月内ROI代理"。 |
| 实际月内ROI代理 | float | 实际D1 × 月内LTV倍率。这不是真实的月内ROI（因为验证之后的长尾还没发生），而是基于LTV曲线的合理近似。用于近似比较两种排序策略对月末ROI的影响方向。 |
| 模型D1_P20 | float | 该单元在新算法下的D1 P20预测值（仅新算法行有实际含义；基线行也填了相同的模型预测值便于对照）。 |
| 模型D1_P50 | float | 该单元的D1 P50预测值。 |
| 基线D1 | float | 该产品在该日期的历史加权平均D1（不论哪种策略都相同）。用于展示每个单元的"旧方法预期"——如果基线D1很高但实际D1很低，说明旧方法在这一单元上失效了。 |

**分析建议**：筛选"策略=新算法P20排序"的行，按 `排序分` 降序排列，观察前10个单元的 `实际D1`——如果排序分最高的单元实际D1也确实高，说明模型排序能力好。同时可以筛选两种策略都选中或都未选中的单元，比较它们的实际D1差异。
