# 智能预算决策系统 — 交付概述

## 1. 项目背景

广告投放运营中，每日预算决策依赖人工经验判断：今天该放量还是控量？各应用各分配多少预算？月末 ROI 能不能达标？

本系统通过机器学习模型对未来一天的消耗和回收率进行预测，结合业务日历和释放曲线，自动为每个应用生成每日预算建议，将预算决策从人工拍脑袋变为数据驱动。

**核心能力：** T+1 消耗预测 → T+1 回收率预测 → 月末 ROI 推算 → 每日预算建议 → 异常告警。

## 2. 系统能力一览

| 能力 | 说明 | 精度 |
|------|------|------|
| 消耗预测 | 预测下一天各应用的广告消耗金额 | MAPE ~58% |
| 回收率预测 | 预测下一天首日回收/消耗比率 | MAPE ~35% |
| 区间估计 | 消耗的 P05/P50/P95 预测区间，支持保守/中性/激进三档预算 | 覆盖率 ~75% |
| 月末 ROI 推算 | 结合释放曲线推算月末累计 ROI | — |
| 每日预算建议 | 基于预测自动生成放量/控量/维稳建议 | — |
| 风控告警 | 8 类异常自动检测（消耗骤降/骤升、ROI 下行、cap 逼近等） | — |
| 收入验证 | 释放曲线模型的反向验证（预测 vs 实际买量收入） | — |

## 3. 系统架构

```
daily_merged.csv (唯一数据源)
       │
       ├──→ T+1 Spend/ROI 预测 (XGBoost, walk-forward)
       ├──→ 释放曲线构建 (per-app 30天ROI倍率)
       ├──→ 月末预算推荐 (求解器 + 规则引擎 + 风控)
       └──→ 收入验证 (释放曲线反向预测)
       │
       ▼
  outputs/ → Web 看板 (ECharts) → 运营决策
```

**技术栈：** Python 3.13, FastAPI, XGBoost/CatBoost/LightGBM, MAPIE(CQR), ECharts 5

## 4. Web 看板四模块

| 页签 | 用途 | 关键交互 |
|------|------|---------|
| 预测模块 | 查看 T+1 模型预测效果 | 切换 Spend/ROI、搜索应用、图表联动、导出 CSV |
| 推荐模块 | 每日预算决策核心面板 | 月末 ROI 预测表、三档预算、六层决策面板、导出 CSV |
| 收入验证 | 释放曲线模型准确性验证 | 实际 vs 预测收入折线图、per-app 曲线诊断、在线预测 |
| 系统监控 | 运维状态总览 | 告警历史、健康趋势（30天）、重训触发 |

## 5. 风控体系

| 告警 | 级别 | 触发条件 |
|------|------|---------|
| 消耗骤降 | CRITICAL | 当日消耗降至近期均值 50% 以下 |
| 消耗骤升 | WARN | 当日消耗升至近期均值 2.5 倍以上 |
| 流量异常 | CRITICAL | 实际收入偏离预测 ≥20% |
| ROI 下行 | WARN | 连续 5 天 ROI 趋势下行 |
| D1 连续下降 | WARN | 连续 3 天 D1 低于预测 90% |
| Cap 逼近 | WARN | 计划预算达到上限的 85% |
| 模型漂移 | CRITICAL/WARN | 预测模型近期误差显著恶化 |
| 重训失败 | CRITICAL | 每日自动重训练步骤执行失败 |

告警持久化到 `outputs/alert_history.jsonl`，Web 监控面板可查。

## 6. 部署与运维

### 启动服务

```bash
pip install -r requirements.txt
PYTHONPATH=. bash scripts/run_web_8000.sh
# 看板: http://localhost:8000/web
```

### 定时重训练

```bash
# 每天凌晨 3 点（crontab -e）
0 3 * * * cd /path/to/ad_ml && PYTHONPATH=. python scripts/daily_retrain.py >> logs/retrain.log 2>&1
```

重训练步骤：数据健康检查 → Spend T+1 重训 → ROI T+1 重训 → 释放曲线更新 → 收入验证。单步超时 2 小时（可通过环境变量调整）。

### 配置

所有参数集中在 `app/config.py`，支持 `APP_` 前缀环境变量覆盖：

```bash
export APP_DEFAULT_KPI=1.08       # 目标 ROI
export APP_API_KEY="your-key"     # API 鉴权（不为空则启用）
export APP_RETRAIN_TIMEOUT_SECONDS=10800
```

### 数据要求

输入文件 `daily_merged.csv`，列：日期、应用ID、消耗金额、首日广告收入、买量广告收入。至少 30 天历史，覆盖 300+ 应用。

## 7. 节假日日历

系统内置 2026 年中国节假日日历 (`data/business_calendar_2026.json`)，自动识别工作日/周末/法定假日/寒暑假，并应用实证校准的 scale 因子修正休息日预测偏差：

| 日类型 | Scale | 依据 |
|--------|-------|------|
| 工作日 | 1.00 | 基准 |
| 周末 | 1.90 | Carryover actual/pred 实证比率 |
| 节假日 | 1.60 | 同上 |
| 寒暑假 | 1.10 | 长周期适度上调 |

```bash
# 2. 运行一次完整重训练（约 10-30 分钟）

# http://localhost:8000/web → 预测模块应有图表数据
# http://localhost:8000/web/recommend → 推荐模块应有应用列表
# http://localhost:8000/web/monitor → 系统监控应有重训状态
```
