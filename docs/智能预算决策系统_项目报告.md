# 智能预算决策系统 — 项目技术报告

## 1. 项目概述

### 1.1 项目定位

智能预算决策系统是一个面向广告投放运营的 T+1 预测与每日预算优化 Web 服务。系统基于历史广告数据，通过机器学习模型预测未来一天的消耗金额和回收率，结合业务日历和释放曲线，自动为每个应用生成每日预算建议（放量/控量/维稳），并通过 Web 看板提供完整的决策链路可视化。

### 1.2 目标问题

项目解决的是"广告投放中每天该花多少钱、预期回收多少、月末 ROI 能否达标"这一运营决策问题。其关键难点包括：

- **预测对象高度异质**：1,800+ 应用的消耗规模从零到数千不等，长尾分布极端（Gini 0.95），小应用噪声大、头部应用影响重
- **休息日效应显著**：目标用户群体（小学生）在周末/节假日/寒暑假的行为模式与工作日差异巨大，不校准会导致系统性低估
- **月末决策压力**：运营需要在月末前几天判断是否达 KPI，而释放曲线受多因素影响（D1 水平、长尾乘数、跨月 carryover）
- **多维度风险**：消耗骤降/骤升、ROI 趋势下行、预算逼近上限等异常需要及时发现并响应

### 1.3 当前系统特征

- 基于 FastAPI 提供 Web 看板和 API 接口
- 两个独立 XGBoost 模型分别预测 T+1 消耗和 T+1 首日回收率
- 基于 MAPIE 的 CQR（Conformalized Quantile Regression）提供消耗预测的 P05/P50/P95 区间
- 通过释放曲线模型将 T+1 预测外推为月末 ROI 估计
- 8 类风控告警自动检测 + 综合风险评分（0-100）
- 六层决策面板（KPI/时间/配置/节奏/风控/决策排序）提供完整决策链路
- 支持 CSV 导出和 API 鉴权

## 4. 当前版本核心算法

当前版本不是"直接用全量数据跑一个模型"，而是一个包含数据过滤、特征工程、多模型训练、区间校准和业务校准的完整流水线。

### 4.1 总体流程

1. 从 `daily_merged.csv` 加载原始数据（创意粒度），按应用+日期聚合消耗和收入
2. 数据健康检查（行数、应用数、日期覆盖、列完整性）
3. 构建统一底表（unified_daily），进行特征工程（滞后特征、滚动统计、日历特征、交互特征）
4. 分别训练 Spend 和 ROI 两个 XGBoost 模型（walk-forward expanding window）
5. 对 Spend 模型应用 CQR 区间估计（分桶校准 P05/P50/P95）
6. 构建 per-app 释放曲线（30 天日级 ROI 乘数）
7. 基于 T+1 预测 + 释放曲线推算月末 ROI
8. 通过求解器 + 规则引擎生成每日预算建议
9. 风控系统检测异常并生成告警

### 4.2 数据过滤策略

系统对训练样本实施两层过滤，以应对极端长尾分布：

| 过滤条件 | 用途 | 保留样本 | 丢弃比例 |
|---------|------|---------|---------|
| spend ≥ 0.01 | Spend 模型训练 | 26,512 | 56.1%（全部为零消耗样本） |
| spend ≥ 2.00 | ROI 模型训练 | 23,659 | 60.8% |

过滤效果：

- **Spend 模型**：去掉 56% 零消耗噪声后，Gini 系数从 0.950 降至 0.825，仍为长尾但可控
- **ROI 模型**：零 ROI 率从 18.8% 降至 0.2%，变异系数（CV）从 2.74 降至 0.38，分布从极度右偏变为接近对称

两个模型均使用 `spend^0.35` 作为样本权重，提升高消耗样本在训练中的影响。

### 4.3 特征工程

Spend 模型约 74 维特征，ROI 模型另有 ROI 专用特征，主要类别：

| 特征类别 | 内容 | 示例 |
|---------|------|------|
| 消耗滞后 | 前 1/2/3/7 天消耗 | `spend_lag1`, `spend_lag7` |
| ROI 滞后 | 前 1/2/3/7 天 ROI_D1 | `roi_lag1`, `roi_lag3` |
| 滚动统计 | 7/14/30 天均值、标准差 | `spend_roll7_mean`, `spend_roll7_std` |
| 日历特征 | 工作日/周末/节假日/寒暑假 | `is_rest_day`, `day_type` |
| 假期交互 | 节前/节后 N 天窗口 | `is_pre_holiday_3d`, `is_post_holiday_3d` |
| 月度节奏 | MTD 消耗、距月末天数、月内周次 | `mtd_spend`, `days_to_month_end`, `week_of_month` |
| ROI 分解 | 单位消耗激活数 × 单位激活收入 | `act_per_spend`, `rev_per_act_d1` |

特征编码采用 expanding-window cumulative mean，避免未来信息泄漏。

### 4.4 训练框架

采用 Walk-forward Expanding Window：

- 最小训练天数：20 天
- 评估窗口：20 天
- 每次预测仅使用截至目标日前一天的数据
- 目标编码在每次 walk-forward 迭代中重新计算

### 4.5 CQR 区间估计

仅对 Spend 模型应用，为每个预测提供校准后的 80% 置信区间：

1. 训练三个 XGBoost 分位数模型（α=0.05, 0.50, 0.95）
2. 对训练集按预测值分桶（Q1-Q4）
3. 在每个桶内独立计算 conformal 校准因子
4. 预测时根据 P50 预测值所在桶应用对应校准因子

目的：处理消耗预测的异方差性（大应用的预测误差绝对值远大于小应用），支持保守/中性/激进三档预算决策。

覆盖率：~75%（目标 80%）。

### 4.6 休息日校准

系统基于 2026 年节假日日历自动判定日期类型，并应用实证校准的 scale 因子修正休息日预测偏差：

| 日期类型 | Scale 因子 | 校准依据 |
|---------|-----------|---------|
| 工作日 | 1.00 | 基准 |
| 周末 | 1.90 | Carryover actual/pred 实证比率 |
| 节假日 | 1.60 | 同上 |
| 寒暑假 | 1.10 | 长周期适度上调 |

校准因子基于 2026-05-19 的 Carryover 总量 actual/pred 比率实证得出：周末 pred=232,712, actual=406,116, ratio=1.745；节假日 pred=229,382, actual=317,821, ratio=1.386。

### 4.7 月末 ROI 推算

月末 ROI 的推算融合三条口径：

| 口径 | 方法 | 适用场景 |
|------|------|---------|
| 稳定锚点（stable） | 基于历史 D1 均值 + 释放曲线 ×30 天推算 | 历史稳定、训练天数充足的成熟应用 |
| 纯预测（pred_only） | 基于 T+1 D1 预测值推算 | 近期波动大、需反映最新趋势的应用 |
| 融合（fused） | 稳定锚点 × 权重 + 纯预测 × (1-权重) | 当前主用口径，兼顾稳定性与时效性 |

主决策口径为 `fused`。

### 4.8 预算求解

基于线性规划为每个应用分配每日预算：

- 约束：总预算上限、单应用 cap、今日消耗不低于昨日的一定比例
- 目标：最大化月末 ROI 盈余
- 输出：每个应用的放量/控量/维稳建议 + 优先级排序

### 4.9 风控体系

8 类自动告警检测 + 综合风险评分（0-100）：

| 告警类型 | 级别 | 触发条件 |
|---------|------|---------|
| SPEND_DROP | CRITICAL | 消耗骤降至近期均值 50% 以下（avg≥30 才触发） |
| SPEND_SPIKE | WARN | 消耗骤升至近期均值 2.5 倍以上 |
| TRAFFIC_ANOMALY | CRITICAL | 实际收入偏离预测 ≥20% |
| PRODUCT_D1_DROP | WARN | 连续 ≥3 天 D1 低于预测 90% |
| ROI_DECLINE_TREND | WARN | 连续 5 天 ROI 非严格递减（含至少一次真下降） |
| CAP_PROXIMITY | WARN | 计划预算达到上限的 85% |
| PREDICTION_DRIFT | CRITICAL/WARN | 模型近期 MAPE 显著恶化 |
| RETRAIN_FAILURE | CRITICAL | 每日自动重训练某步骤执行失败 |

风险评分公式：CRITICAL 告警 +25 分，WARN 告警 +10 分，ROI 低于 KPI 每 0.01 加 1 分，上限 100。

## 5. 当前版本的性能优化点

### 5.1 样本过滤

通过 min_spend 阈值过滤掉 50%+ 的噪声样本，不仅提升模型精度，也显著减少训练时间。

### 5.2 GPU 加速

XGBoost 使用 GPU 直方图算法（`tree_method='hist'`, `device='cuda'`），相比 CPU 训练提速 5-10 倍。

### 5.3 服务启动预热

Web 服务启动时预加载模型评估数据到内存（约 40 秒），后续所有请求瞬时响应，无磁盘 I/O 等待。

### 5.4 重训练并行化

Spend 和 ROI 两个模型可独立并行训练。当前版本为串行执行以保证稳定性，但架构支持改造为并行。

## 8. 当前系统优点与局限

### 8.1 优点

- 不是纯规则系统，具备机器学习预测能力，能捕捉消耗和 ROI 的时序规律
- 休息日实证校准基于历史实际数据，非主观设定，显著改善休息日预测偏差
- CQR 区间估计提供校准后的置信区间，支持不同风险偏好的预算决策（保守/中性/激进）
- Walk-forward 训练框架确保无数据泄漏，评估结果真实可信
- 六层决策面板提供从 KPI 到最终决策的完整链路可视化，非黑箱
- 8 类风控告警覆盖消耗异常、ROI 下行、预算逼近、模型漂移等多维度风险
- 环境变量配置支持零代码改参，部署灵活

### 8.2 局限

- Spend 模型 MAPE 约 59%，对于消耗极小的应用预测误差绝对值虽小但百分比高
- 释放曲线模型假设历史 cohort 行为可外推，对新产品或市场突变场景精度有限
- 当前缺少自动化 A/B 测试框架，校准因子的更新依赖人工分析
- 模型重训练依赖 GPU，无 GPU 环境下降级为 CPU 训练耗时显著增加
- 当前无多租户/权限分级，适合单团队使用
